研究時間：2026-11-24（本輪歷史快照）

公開入口：[Threads @johnny850807](https://www.threads.com/@johnny850807) ｜ [Waterball Software Academy / aixbdd](https://github.com/Waterball-Software-Academy/aixbdd) ｜ [AI-Native Global Founders Speedrun Taiwan](https://github.com/AI-Native-Global-Founders-Speedrun-TW/ai-native-founders-tw-mono)

## 為什麼研究他

從公開貼文裡看到 AI Coding、軟體工程與知識轉成工作流程的做法，想弄懂其中有哪些概念能用到自己的學習與工作。這不是人物傳記、能力評比或課程推薦。

## 怎麼研究

先讀公開貼文，再對照相關 GitHub 文件、PR 與公開紀錄；區分提出的方法、實際可見的產出與尚未證實的成效。由研究者挑選自己有興趣的題目，而不追求一篇介紹完所有研究結果。

- [EVIDENCE.md](EVIDENCE.md)：代表性公開來源與證據邊界。
- [POST.md](POST.md)：文章狀態；本人定稿前不公開草稿。

## 本輪選擇：先有可修改的 SOP，再學習

研究者選了第二個視角，其餘留待未來，不塞進同一篇文章。

依 W01 的轉述，先把目前的做法寫成粗略流程，學習時再辨識哪個步驟或決策需要修改。可將它理解為先建立一個可修正的基底，而不只是蒐集筆記。這是對方法的理解，尚無本案例的實驗結果。

### 可以追問

- 哪些類型的知識適合立刻更新工作流程？哪些知識需要時間沉澱？
- 若沒有現成工作流程，先寫粗糙版本是否真的有幫助？
- W08 所載先試跑再修 SOP 是較早的組織實踐，可作對照，但不是 W01 學習方法有效的證明。
